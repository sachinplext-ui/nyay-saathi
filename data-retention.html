वर्तमान प्रोटोटाइप

अभी NYAY SAATHI में user accounts, case database, document upload, evidence vault या online filing चालू नहीं हैं। आवेदन जनरेटर टेक्स्ट को ब्राउज़र में format करता है और NYAY SAATHI server को नहीं भेजता। इसलिए प्रोजेक्ट के पास वर्तमान में हटाने के लिए user case records नहीं हैं।

Browser service worker static assets cache कर सकता है। उपयोगकर्ता browser settings से site data/cache साफ़ कर सकते हैं। Hosting provider के technical logs उनकी अपनी policies और retention practices के अनुसार संभाले जाते हैं।

भविष्य में व्यक्तिगत डेटा सुविधा चालू करने से पहले

  1. Data inventory: कौन-सा field/file लिया जाएगा, क्यों आवश्यक है और क्या इसे टाला जा सकता है।
  2. Retention अवधि: हर data category के लिए स्पष्ट अवधि और शुरुआत का बिंदु तय करें; डेटा अनिश्चितकाल तक न रखें।
  3. Deletion प्रक्रिया: user request, account closure, expired records, backup expiry और deletion confirmation की प्रक्रिया लिखें।
  4. Backups: हटाया गया डेटा backup से कब हटेगा और restore के बाद हटाया डेटा वापस न आए, यह तय करें।
  5. Legal holds: कानूनन आवश्यक होने पर सीमित और समीक्षा की गई प्रक्रिया रखें; जहाँ कानून अनुमति दे, प्रभावित व्यक्ति को सूचित करें।
  6. Processors: hosting, identity, storage, email, analytics और AI providers तथा उनकी retention settings और contracts दर्ज करें।
  7. Audit: हटाने की request पूरी होने का रिकॉर्ड रखें, लेकिन हटाए गए दस्तावेज़ की सामग्री न रखें।
  8. Rights and contact: access, correction, export और deletion requests के लिए जिम्मेदार संपर्क और प्रक्रिया प्रकाशित करें।

डेटा कम से कम रखने के प्रस्तावित नियम

  • सिर्फ़ registration के लिए Aadhaar, PAN, bank details, passwords, OTPs, पूरी FIR या सटीक घर का पता न लें।
  • Development और QA में केवल काल्पनिक डेटा रखें।
  • Private storage, access control, malware scanning, encryption, retention, deletion और स्वतंत्र सुरक्षा समीक्षा तैयार होने तक file uploads बंद रखें।
  • User documents को public GitHub repository या public website directory में कभी न रखें।

Launch से पहले अनिवार्य शर्त

Qualified privacy/legal और security reviewers की मंज़ूरी, data inventory, notice, retention schedule, deletion workflow, child-safety/age eligibility और incident-response प्रक्रिया पूरी होने तक कोई personal-data collection या document storage चालू नहीं होगा। Hosting, accounts और production secrets पर trusted adult project owner की निगरानी आवश्यक है।

English

Current prototype

No NYAY SAATHI user accounts, case database, document upload, evidence vault or online filing are enabled. The application generator formats text in the browser and does not send the draft to the NYAY SAATHI server. The project therefore does not currently maintain user case records to delete.

The browser service worker may cache static assets. Users can clear site data/cache in browser settings. Hosting-provider technical logs are governed by that provider's own policies and retention practices.

Before enabling any future personal-data feature

  1. Data inventory: document every field/file collected, why it is needed and whether it can be avoided.
  2. Retention period: define a period and start point for each category; do not retain data indefinitely by default.
  3. Deletion workflow: document user-requested deletion, account closure, expired records, backup expiry and confirmation.
  4. Backups: define when deleted records expire from backups and prevent restoration from resurrecting deleted data.
  5. Legal holds: use a narrowly scoped, reviewed process where legally required; notify affected people where lawful.
  6. Processors: document hosting, identity, storage, email, analytics and AI providers, their retention settings and contracts.
  7. Audit: record that a deletion request was processed without retaining deleted document contents.
  8. Rights and contact: publish a responsible contact and process for access, correction, export and deletion requests.

Proposed data-minimization defaults

  • Do not collect Aadhaar, PAN, bank details, passwords, OTPs, full FIR copies or precise home addresses merely for registration.
  • Keep development and QA data synthetic.
  • Disable uploads until private storage, access control, malware scanning, encryption, retention, deletion and independent security review are ready.
  • Never store user documents in the public GitHub repository or public website directory.

Launch gate

No personal-data collection or document storage may be enabled until qualified privacy/legal and security reviewers approve the data inventory, notice, retention schedule, deletion workflow, child-safety/age eligibility and incident-response process. A trusted adult project owner must oversee hosting, accounts and production secrets.
